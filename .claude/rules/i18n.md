# Internationalization (i18n)

## Architecture

- All user-facing **system/UI strings** are localized via `src/shared/i18n/`
- The active locale is set by the `LOCALE` environment variable (`it` or `en`)
- **LLM/agent responses** are NOT localized through i18n — SLANG workflow instructions tell agents to respond in the user's language

## How to Use

Access translated strings via the `MESSAGES` object (which delegates to `t()` internally):

```typescript
import { MESSAGES } from '@shared/messages.js'

await ctx.reply(MESSAGES.WELCOME)
```

Or use `t()` directly:

```typescript
import { t } from '@shared/i18n/index.js'

const text = t('WELCOME')
```

## Adding a New String

1. Add the key to `MessageKeys` type in `src/shared/i18n/types.ts`
2. Add the Italian translation in `src/shared/i18n/locales/it.ts`
3. Add the English translation in `src/shared/i18n/locales/en.ts`
4. Add a getter to `src/shared/messages.ts` (if it should be accessible via `MESSAGES`)

## Rules

- Never inline user-facing strings in handlers or adapters
- Every key in `MessageKeys` must have a translation in **all** locale files
- Keep translation files in sync — the i18n test verifies completeness
